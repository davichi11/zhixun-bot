# 技术事实核查

## 核心原则

> **写不出处的事实，就是编的。**

读者查你文章里的 star 数、版本号、能力边界，是最快的信任崩塌方式。

## 必须核实的四类断言

| 类型 | 例子 | 核实方式 |
|---|---|---|
| **数字** | "12k stars"、"支持 100+ 模型" | 查官方仓库 / 文档 |
| **版本** | "Agno 3.1 新增了 X" | 查 release notes / changelog |
| **能力边界** | "它支持 MCP" | 查官方文档，**不要靠推理** |
| **对比结论** | "A 比 B 快 3 倍" | 找基准测试原文；找不到就删掉这句 |

## 核查流程

### 1. 先判断这条事实有多重要

- **写进标题的事实** → 必须核实，无例外
- **正文里的关键数字** → 必须核实
- **顺带一提的例子** → 可以标注"未经核实"

### 2. 找到一手来源

优先级：
1. **官方仓库的 README / docs** > 2. 官方文档站 > 3. release notes > 4. 技术博客 > 5. 二手文章

**永远不要**用二手文章核实一手事实 —— 它可能已经过时。

### 3. 记下出处

```markdown
> Agno 3.1.2 起，`HumanReview` 只在顶层 `Step` 生效。
> —— 来自官方 Workflow 文档 + 本项目对照实验
```

### 4. 核不实的怎么办

**删掉，或者明确标注不确定。**

三个选项，按优先级：
1. 删掉这句话
2. 改成"据官方文档提到，应该支持……"（降级为转述）
3. 标上"⚠️ 未核实"（最后手段，读者会反感）

## 常见的"看起来合理但错误"写法

| 别写 | 写成 |
|---|---|
| "该框架支持所有主流模型" | "该框架文档列出了 OpenAI、Anthropic 等 5 家" |
| "性能比 X 快 3 倍" | （删掉） |
| "这是最好的 Agent 框架" | （删掉，主观断言不写进技术文章） |
| "即将支持 MCP" | "官方仓库有一个标为 `wip` 的 MCP 分支" |

## 收尾自查

发布前问自己三个问题：

1. 这篇文章里，有哪几个数字？**它们各自的一手来源在哪？**
2. 有没有哪句话，是在描述"框架**应该**怎么做"而不是"框架**实际**怎么做"？
3. 如果读者逐条来质疑，我能拿出什么？

三个问题里有任何一个答不上来，就把那句话改掉。
